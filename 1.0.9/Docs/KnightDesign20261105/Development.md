# 后续精细版本开发与交接

> 本文件记录 V1 接口和交接推导。当前运行资源已切换到 Refined 配置、细化模型及八招，新增来源和实际验证见 [V2 设计](RefinementV2/Design.md)。原公共契约、三Boss与正式剧情的未完成边界继续有效。

## 1. 当前实现边界

当前是完整剑盾 1.0.6 上的**独立骑士招式原型**，用于冻结尺度和交互。主场景未替换，旧典狱长仍可开始；没有合入其他分支整套故事和三水晶斗场，没有实现缚魂者、亡灵增援、跨关装备、永久奖励、正式选择或结局存档。

原型使用现有 `BossEncounter` 的进入、玩家、HUD、伤害、暂停、重试和返回流程，骑士行为以独立 partial 文件接入。它避免复制第二个玩家，但还不是团队 v0.4 建议的公共三 Boss 架构。正式收取时应由公共维护者把这些窄接入口迁移到统一契约，不应继续无限扩展一个巨型控制器。

`KnightTrialLauncher.storyGate=false` 为默认完整战斗测试。设为 true 后，首次跨过 20% 请求 `knight.final_decision` 并冻结；当前界面只有继续挑战/返回，不会伪装成正式三结局选项。

## 4. 正式接口建议

正式版本沿用团队 v0.4 的公共职责，不把本原型的私有字段反射当作生产接口：

| 接口 | 骑士需要提供/接收的内容 |
| --- | --- |
| 战斗会话 | Start/Pause/Resume/Retry/End/Cleanup 与合法状态，进入前验证 Arena/出生点 |
| Boss 状态 | ID=`knight`、显示名、生命、阶段、可受伤、当前预警与锁定状态 |
| 伤害请求 | 来源 ID/位置、目标、阵营、伤害类型、可格挡、可弹反、唯一命中 ID |
| 剧情请求 | `knight.final_decision`、请求 ID、当前阈值、需要的恢复上下文；事件只发一次 |
| 选择返回 | Continue/PhaseChange/Ceasefire/Complete，不在骑士内按中文按钮算结局 |
| 结果 | 胜利、失败、停战、退出；挑战结果与主线结果分开 |
| 本轮进度 | 只读装置、援军、救援完成、担保等事实；奖励由公共层一次性提交 |

20% 阈值的持久语义需要“未触发/待确认/已提交”。当前只有会话内标志，退出后不保存；正式版应将关卡血量、攻击取消、选择和检查点原子恢复，避免只存一个布尔值导致读档跳过对话。

多目标伤害接入后，方向盾防使用实际来源位置，优先级在“守门职责目标/近处真实威胁”之间选择。不得读取召唤组私有控制器，或把友方亡灵直接写成玩家附加伤害。没有援军的克制路线必须能独自通关。

## 5. 精细开发的依赖顺序

### 第一阶段：冻结战斗规则

用极简模型完成真人完整战斗。记录每招读取率、死因、体力耗尽次数、真实时长与不公平位置。确定第三斩是否改窄下劈、突刺是否改连续扫掠；这些会影响动画，必须在正式动作制作前定下。

交付：唯一参数表、每招判定图、当前资产快照与验证记录。结束标准：每招至少有一种可靠低成本解法；无预警伤害、锁向后追转、盾击瞬发和无限举盾均消除。

### 第二阶段：公共接口与单关白盒联调

由公共维护者迁移 BossEncounter 的窄分支，骑士只持有自己行为和资源。同一玩家与 HUD 能进入典狱长、召唤占位和骑士；跑通暂停、失焦、死亡、重试、停战和退出。先接多目标伤害，再正式接友军亡灵。

交付：接口版本、适配器、单关测试场景、事件/选择 ID 清单。没有接口版本时继续做模型和招式表现，不各自复制玩家、存档或奖励系统。

### 第三阶段：角色和动作替换

先按 BossDesign 的比例做低模、骨架和挂点，把现有时序完整复现。优先检查持剑手、盾臂、脚底与重心；用真实武器轨迹替换几何姿态，不通过修改伤害时间迁就错误动画。

交付：可编辑建模源、游戏模型、材质、动画、Prefab 与 `.meta`。现有原型保留为回归样本。每次替换完成后重新验证连段打断、突刺扫掠、第三斩高度与收招窗口。

### 第四阶段：场景和攻击表现精细化

按 ArenaDesign 先加门框与导流结构，再加叙事物件、材质灯光。按 MoveDesign 给预警增加形状和动态，飞矛增加待发形态，地带增加薄光幕，盾防增加方向火花。声音按动作里程碑发出，停战清理剩余攻击音。

交付：角色与场景在真实玩家镜头中的多角度截图、每招动态片段、两阶段对照。静帧不能验收全部动作。

### 第五阶段：剧情、跨关与发行

接入事实条件和正式选择，完成无援军/有援军两套配置；确认装置扣生命的具体规则，骑士组不擅自定义。完成三种收尾行为后由公共流程结算，不能仅点按钮就结束。

最后才去掉测试场景未使用的大堂资源、做 LOD/剔除与正式构建。记录目标设备、分辨率、画质、帧时间、峰值弹体和友军数。未测设备不写“性能通过”。

## 6. 本轮验证与复查

[RuntimeChecks.cs.txt](RuntimeChecks.cs.txt) 为受控 Play Mode 检查方法体，通过 MCP `execute_code` 执行，不进入游戏编译。[RuntimeChecks.json](RuntimeChecks.json) 保存 31 项实际结果，全部通过。检查中暂停自动 AI 与控制器推进，调用正式战斗/受击/技能方法并同步物理；不是完整人工战斗录像或输入端到端测试。

覆盖：单一玩家与原配置、出生地面、双斩时序和单次命中、真实受击入口弹反取消后续斩、盾防正背面、反制前摇、玩家数字 2 盾击真实打断、锁向、三枚弹体和清理、地带安全区与命中、二阶段第三击、暂停、胜负、重试、剧情大伤害跨阈值、待确认免伤、继续/返回及旧典狱长仍能开始。

本轮尚未完整验证：真实输入吞印/弹反/极限闪避全路径、友军亡灵、剧情存档、全部低帧率边界、完整真人获胜、独立构建、LOD与性能。飞矛沿用旧吞印实现，薄墙边界需专项回归；这是开发任务，不应被 31 项数字掩盖。

脚本编译后须检查 Console。过程中曾在 Play Mode 热重载触发 Input System 的 Map 索引断言，应退出 Play 后重新进入验证；不能将历史热重载日志清空后冒充从未出现过。最终干净重入与 Console 状态另记于 FinalVerification.json。

## 7. 精细版本验收清单

| 范围 | 必须实际验证 |
| --- | --- |
| 连斩 | 两/三次独立预备可读；打断后不补刀；实际剑迹与范围一致 |
| 突刺 | 锁向后不追转；碰墙缩短；低帧率不穿墙；伤害和冲势语义唯一 |
| 飞矛 | 待发无伤害；墙前/墙后吞印正确；碰撞与消散一致；一枚一次 |
| 地带 | 安全区可达；跳跃高度和光幕一致；二阶段中线规则清楚 |
| 盾防 | 仅声明时间与方向有效；真实盾击能拆；多来源各算各的方向 |
| 生存资源 | 无援军可通关；全防耗尽有明确提示；保留移动/跳跃解法 |
| 生命周期 | 失焦/暂停/时停/剧情均冻结；死亡/退出立即清理；连续重试不累积 |
| 剧情 | 致死高伤不跳阈值；同帧死亡优先级固定；选择/奖励只提交一次 |
| 场景 | 出生点、绕盾、贴墙、空中、门边、镜头、返回脚点全部可用 |
| 资源 | 无 Missing Script、丢网格、重复 GUID、缺中文字形或粉红材质 |
| 发行 | 正式入口可进入并完成；真人、独立包和目标设备另有证据 |

本轮未提交或推送远端，也未创建新归档版本号。后续收取应挑选本次文件和公共接入变化，保留其他成员工作区内容。
